# Gemini CLI Coordination File for NextRead Frontend

This file provides context and coordination guidelines for Gemini CLI's contributions to the NextRead Frontend project, ensuring effective collaboration in a multi-agent development environment.

## 1. Project Context

NextRead Frontend is a React/TypeScript application that serves as the user interface for the NextRead book tracking application. It uses Redux for state management, modern UI components, and integrates with the NextRead backend API to provide book search, recommendations, and user management functionality.

## 2. Your Role

As Gemini CLI, your primary roles in this project are:
- **Primary Coder & Reasoning Agent:** Implementing new features, fixing bugs, and refactoring code.
- **File Summarization:** Providing concise summaries of files and code sections to aid development.
- **Brainstorming & Planning:** Assisting in brainstorming new ideas and planning development tasks.

## 3. Key Coordination Files

To maintain context and align with the project's direction, always reference the following files:

- **`DEV_LOG.md`**: The authoritative source for project history, ongoing tasks, and development status. **Check this file first.**
- **`README.md`**: Project overview, setup instructions, and build documentation.
- **`claude.md`**: The coordination file used by the Claude Code agent. Review it for insight into Claude's context and directives.
- **`src/`**: React/TypeScript application source code with components, features, and pages.

## 4. Multi-Agent Guidelines

To ensure smooth collaboration with other AI agents (like Claude Code and ChatGPT):

- **Consult Before Overwriting:** Do not overwrite code or files generated by other agents without first understanding the context from the `DEV_LOG.md`.
- **Check `DEV_LOG.md` First:** Always check the `DEV_LOG.md` to understand the current project state and active tasks before starting any work.
- **Log Your Work:** Add new entries to `DEV_LOG.md` with a timestamp (Eastern Time) and your model name (e.g., `Gemini-Pro`) to document your changes.
- **Coordinate via Docs:** Use the shared documentation (`DEV_LOG.md`) as the primary means of coordination.
- **Backend Coordination:** When making API changes that affect the backend, note required backend updates in `DEV_LOG.md`.

## 5. Current Focus

The immediate priority is setting up the multi-agent development workflow and ensuring proper documentation is in place for coordinated development between frontend and backend teams.
